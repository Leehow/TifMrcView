# TifMrcView

Небольшая, быстрая и удобная программа для просмотра изображений микроскопии и электронной микроскопии: TIFF / OME-TIFF / ImageJ, MRC для крио-ЭМ и крио-ЭТ, Zeiss CZI и SmartSEM. Рисуйте линии, прямоугольники и окружности с измерениями в физических единицах, переключайтесь между видами XY / XZ / YZ и просматривайте многоканальную флуоресценцию с включением и цветом для каждого канала. Установщик занимает всего несколько МБ, но мгновенно открывает стеки на несколько ГБ. Работает в macOS, Windows и Linux и расширяется плагинами. Создана на Rust + Tauri 2.

## Возможности

- Поддерживаемые форматы: TIFF (многостраничный, полосы/тайлы, сжатие LZW/Deflate/PackBits/JPEG, градации серого 1–7 бит, например 1-битный бинарный и 4-битный, а также 8/16/32-битные целые и с плавающей точкой; необычные разрядности вроде 12 бит дают понятное сообщение об ошибке), OME-TIFF (читает измерения C/Z/T, названия и цвета каналов, размер пикселя), гиперстеки ImageJ (включая непрерывно записанные файлы больше 4 ГБ), TIFF с палитрой (например, SEM-изображения Zeiss), MRC/MRC2014 (режимы 0/1/2/3/4/6/12/101, `.mrc` `.mrcs` `.rec` `.st` `.map`; для файлов режима 0 без метки IMOD по минимуму/максимуму в заголовке определяется, беззнаковые ли это байты) и, с плагином Zeiss, Zeiss CZI (LSM / Airyscan и др., сохранённые ZEN: несжатые, Zstd и JPEG-субблоки, 8/16/32-битные серые и цветные, измерения C/Z/T, тайловые мозаики, названия и цвета каналов, размер пикселя). `.rec` `.st` `.map` и `.czi` появляются только в «Открыть с помощью» и не назначаются программой по умолчанию
- Также открывает PNG / JPEG / BMP / GIF / WebP
- Ползунок Z и воспроизведение; при наличии временного измерения — ещё и ползунок T
- Объёмная ЭМ (FIB-SEM, серийные срезы, SBF-SEM): папка изображений срезов открывается как один Z-стек (перетащите папку в окно или кнопка папки / Ctrl/⌘+Shift+O); срезы могут быть в любом формате, который открывает приложение, и читаются только по мере надобности. Если плагин распознаёт рядом файл проекта съёмки (`ProjectData.dat` Thermo Fisher Auto Slice & View с плагином `thermo`), в списке миниатюр этой папки появляется элемент стека с толщиной среза в качестве шага по Z; иначе шаг по Z можно ввести в разделе «Масштабная линейка»
- Многоканальная цветная композиция: флажок показывает/скрывает канал, щелчок по названию настраивает контраст этого канала, щелчок по точке меняет его цвет
- Яркость / контраст / гамма; перетаскивание по гистограмме сразу задаёт отображаемый диапазон; по умолчанию автоконтраст для каждого среза (насыщение 0,1 %)
- Кнопка ⓘ на панели инструментов показывает информацию об изображении: формат, размер, размер пикселя и параметры съёмки, прочитанные плагинами (с поиском и копированием). Плагин Zeiss читает все параметры SEM-изображения Zeiss SmartSEM (напряжение, рабочее расстояние, увеличение, детектор, положение столика, вакуум и др.) и показывает масштабную линейку по калиброванному размеру пикселя, а из CZI — микроскоп, объектив, лазеры, детекторы, пинхол, параметры сканирования и обработки Airyscan
- Панель предпросмотра справа (сворачиваемая) перечисляет изображения из той же папки с именем файла, форматом и размером
- Панель значков вверху (названия при наведении): сохранить изображение, отменить, выбор, перемещение, измерение, карандаш (стрелка рядом открывает меню: произвольная линия / линия / стрелка / прямоугольник / окружность), текст, обрезка, масштабная линейка, яркость/контраст
- Измерения показывают реальные длины по размеру пикселя; прямоугольники и окружности всегда подписаны на изображении как ширина × высота (диаметр — для правильной окружности)
- Инструмент выбора (по умолчанию): перетаскивание по пустому месту сдвигает изображение; щёлкните по аннотации, чтобы перетащить её, тяните точки на рамке, чтобы изменить размер, тяните концы линии измерения, чтобы измерить заново; Delete удаляет; можно менять цвет и толщину линии
- Аннотации хранятся отдельно для каждого среза Z и примерно через 2 секунды после рисования автоматически сохраняются в `<имя файла>.annot.json` рядом с изображением, а при следующем открытии читаются обратно
- Обрезка: выделите область, затем двойной щелчок или Enter — будет виден только этот фрагмент; Esc или Backspace отменяет
- IMOD-модель (`.mod` / `.fid`) с тем же именем накладывается автоматически, её можно включать и выключать по объектам
- Сохранение изображения: PNG в исходном разрешении (после обрезки — только обрезанная область) с видимыми аннотациями, моделью и масштабной линейкой
- Изображения с Z можно переключать вверху между видами XY / XZ / YZ (аннотации, нарисованные в боковых видах, не сохраняются)
- Тяните внутренний край левой панели инструментов и правой панели предпросмотра, чтобы изменить их ширину
- Колесо мыши — масштаб, перетаскивание — сдвиг, двойной щелчок — по размеру окна; строка состояния показывает координаты пикселя и исходное значение
- Перетащите файл в окно, чтобы открыть его; двойной щелчок по другому файлу из той же папки открывает его в существующем окне, а файл из другой папки — в новом окне
- Кнопка «Открыть папку» вверху панели предпросмотра показывает текущее изображение в Finder / Проводнике
- При любом другом инструменте щелчок правой кнопкой по изображению возвращает инструмент выбора
- Аннотацию можно показывать только на одном срезе или на диапазоне Z; после выделения Z меняется вверху, а на ползунке Z отмечаются срезы с аннотациями

## Плагины

В меню «Плагины» на панели инструментов можно включать и выключать, устанавливать и удалять плагины, а также проверять обновления. Кроме языков, каждый плагин устанавливается отдельно: нажмите «Каталог плагинов», чтобы открыть в браузере https://tifmrcview.com/tifmrcview/plugins/ и скачать пакет плагина (.zip), затем нажмите «Загрузить плагин…» и выберите его. Установка более новой версии того же плагина просто заменяет старую. Исходный код плагинов находится в репозитории в `plugins/<id>/` (`plugin.json` + `index.js`; сейчас это `recorder`, `zeiss`, `lasx`, `nis`, `fluoview`, `imaris`, `gatan`, `thermo` и `tvips`); установленные плагины лежат в подпапке `<id>/` папки плагинов.

Установка в один клик (0.5 и новее): нажмите **Установить** на карточке плагина в каталоге или в списке «Каталог плагинов» в меню «Плагины» (там же появляется «Обновить до x.y.z», если вышла новая версия). Сайт передаёт приложению ссылку вида `tifmrcview://install-plugin?id=<id>` (можно с `&version=<x.y.z>`); приложение показывает название и описание плагина и ничего не устанавливает, пока вы не нажмёте **Установить**. Устанавливаются только плагины из официального каталога (`plugins.json` рядом с лентой обновлений): они скачиваются по HTTPS, а перед установкой проверяются размер и SHA-256. Способ «скачать zip и нажать „Установить плагин…“» по-прежнему работает.

Плагины форматов: пакет плагина может также добавлять форматы файлов и чтение метаданных в виде изолированного модуля WebAssembly, написанного, например, на Rust с SDK из `plugins/sdk`. Так устроен плагин каждого производителя (`zeiss` открывает CZI и LSM и читает параметры SmartSEM), поэтому в самой программе нет кода форматов производителей: без плагина Zeiss файлы .czi не открываются, и программа подсказывает, какой плагин установить. Модуль видит только открываемый файл, работает с ограничениями памяти и времени и описывает каждую страницу как список фрагментов файла, которые программа сама распаковывает и собирает параллельно. ABI, ограничения и пример — в [docs/format-plugins.md](docs/format-plugins.md).

Плагин записи видео: в панели «Инструменты» в разделе «Запись видео (MP4)» выберите Z или T, начальный и конечный кадры, частоту кадров, область (всё изображение / выделение / текущий вид), размер и качество. Получившийся MP4 (H.264) содержит текущий контраст, цвета каналов, аннотации и масштабную линейку.

Язык интерфейса тоже реализован встроенным плагином (`ui/plugins/i18n.js`): он поддерживает 中文, English, Deutsch, 日本語, Español, Français и Русский, по умолчанию следует языку системы и переключается выпадающим списком на панели инструментов. Он заменяет известные китайские тексты интерфейса на выбранный язык, поэтому переводятся и другие плагины, и сообщения; чтобы добавить новый текст, добавьте строку в `WORDS` (фиксированный текст) или `PATTERNS` (текст с числами или именами файлов). При отключении этого плагина интерфейс возвращается на китайский.

Собственный плагин: положите файл `.js` в папку плагинов и нажмите «Перезагрузить». Для распространения упакуйте `plugin.json` (`id`, `name`, `version`, `description`, `main`, `apiVersion`, `minAppVersion`, при желании `author`, `i18n`, `details`; формат см. в `plugins/recorder/plugin.json`) вместе со скриптом в zip (файлы в корне архива). Минимальный пример:

```js
TifMrcView.register({
  id: "hello",
  name: "Hello plugin",
  version: "1.0.0",
  description: "Shows the current slice in the tools panel",
  activate(app) {
    const box = app.ui.addToolSection("Hello");
    app.on("slice", ({ z }) => (box.textContent = `Slice ${z + 1}`));
  },
});
```

`app` предоставляет: `state()` (текущий файл, Z/T, размер, выделение, размер пикселя), `on("open" | "slice" | "render", fn)`, `setZ` / `setT` / `open(path)`, `renderRegion(region, {z, t, size})` (рендерит в canvas с текущими настройками отображения, включая аннотации и масштабную линейку), `ui.addToolSection` / `ui.addToolbarButton` / `ui.addToolbarSelect` / `ui.toast` / `ui.busy`, `dialog.save`, `fs.write`, `settings.get/set`, а также `native(method, args, bytes)` для вызова стороны Rust. Полное описание — в `ui/plugin-host.js`. Плагины, которым нужен нативный код (например, H.264-кодер для записи), реализуют `NativePlugin` в `src-tauri/src/plugins/`; нативная часть компилируется в основную программу, но включается только после установки пакета плагина с тем же id. Включение записи в сборку управляется Cargo feature (`recorder` включён по умолчанию; `--no-default-features` убирает его, и установщик становится примерно на 1 МБ меньше).

У плагинов те же права, что и у основной программы: устанавливайте только плагины, которым доверяете.

## Автоматические обновления

Через несколько секунд после запуска приложение тихо проверяет `https://tifmrcview.com/tifmrcview/latest.json`. Когда есть новая версия, на шестерёнке (настройки) появляется только маленькая красная точка, без плашек и окон. В меню шестерёнки виден пункт «Доступна версия x.y.z», и точка для этой версии исчезает; пункт открывает «Плагины и обновления», где «Обновить до x.y.z» скачивает обновление, проверяет подпись, устанавливает и перезапускает программу. Пакеты обновлений подписаны ключом minisign Tauri; открытый ключ записан в `tauri.conf.json`.

## Почему это быстро

- Файлы читаются через отображение в память, а полосы/тайлы одной страницы распаковываются параллельно на всех ядрах процессора
- После открытия файла остальные срезы Z заранее декодируются в память в фоне, начиная с ближайших к текущему (примерно четверть физической памяти, 512 МБ–8 ГБ), поэтому при перетаскивании ползунка изображения появляются сразу
- Рендерится только видимая область и только в разрешении экрана; 8-битный RGBA передаётся в интерфейс в двоичном виде, поэтому масштабирование и сдвиг изображения 4000×4000 остаются плавными
- Миниатюры создаются в отдельном пуле потоков и не отнимают процессор у текущего изображения
- Интерфейс — чистый HTML/JS без фронтенд-фреймворка; релизные сборки используют LTO и strip, установщики занимают около 4–11 МБ (Linux AppImage включает WebKit, поэтому около 84 МБ)

## Установка

Скачивайте с официального сайта **[tifmrcview.com/tifmrcview](https://tifmrcview.com/tifmrcview/#download)**. Новые версии выходят часто и публикуются только там (GitHub Releases не используются); приложение обновляется оттуда же:

- **macOS** (10.15 или новее): `TifMrcView_x.y.z_universal.dmg` (Intel и Apple silicon), перетащите в «Программы». Поскольку у приложения нет подписи разработчика Apple, первый запуск блокируется: откройте «Системные настройки → Конфиденциальность и безопасность» и нажмите «Всё равно открыть» либо выполните в терминале `xattr -dr com.apple.quarantine /Applications/TifMrcView.app`. При первом запуске TifMrcView назначает себя программой по умолчанию для .tif/.tiff/.mrc.
- **Windows**: `TifMrcView_x.y.z_x64-setup.exe`, установка двойным щелчком (права администратора не нужны). Установщик регистрирует ассоциации для .tif/.tiff/.mrc; если раньше вы вручную выбирали для .tif другую программу (например, «Фотографии»), Windows не позволяет программам менять это втихую — нажмите «Сделать по умолчанию» в TifMrcView, откроется страница системных настроек, и выберите там TifMrcView.
- **Linux**: `.deb` для Debian/Ubuntu, `.rpm` для Fedora и подобных, `.AppImage` для остальных дистрибутивов. При первом запуске приложение назначает себя программой по умолчанию через `xdg-mime`.

## Сборка из исходников

Нужны Rust (stable) и Node.js 18+. В Linux дополнительно:

```sh
sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev libxdo-dev libssl-dev
```

Затем:

```sh
npm install
npm run dev      # режим разработки
npm run build    # собрать установщик для текущей ОС, в src-tauri/target/release/bundle/
```

Для отладки декодирования есть небольшая встроенная утилита; она выводит метаданные, пиксели по каналам и время декодирования/рендеринга:

```sh
cd src-tauri && cargo run --release --example probe -- /path/to/file.tif
```

## Выпуск релизов

Номера версий формируются автоматически: мажорная.минорная версия из `tauri.conf.json` (сейчас 0.3) плюс общее число коммитов, например `0.3.57`; при отправке тега `v1.2.3` используется версия тега.

Каждый push в `main` запускает в GitHub Actions сборку пакетов для macOS / Windows / Linux; установщики лежат в Artifacts этого запуска. Опубликовать на сайте загрузок можно двумя способами:

- отправить тег, начинающийся с `v`: `git tag v0.3.0 && git push origin v0.3.0` выгружает на сайт загрузок и создаёт GitHub Release;
- или вручную запустить build в Actions, отметив «опубликовать на сайте загрузок»: публикация пойдёт с автоматическим номером версии.

При публикации CI кладёт установщики и пакеты обновлений в каталог `<версия>/` сайта загрузок и в конце обновляет `latest.json` (для автообновления) и `downloads.json` (для страницы загрузки). Пакеты каталога плагинов (`plugins/`) также разворачиваются отдельным workflow (`.github/workflows/plugins.yml`) при любом изменении в `main`; сами страницы сайта хранятся в отдельном репозитории. Нужно настроить в репозитории в Settings → Secrets and variables → Actions:

| Имя | Тип | Описание |
| --- | --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | Secret | Закрытый ключ для подписи пакетов обновлений (если он потерян, обновления уже установленным пользователям отправить нельзя) |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | Secret, необязательно | Пароль этого ключа, если он задан |
| `DEPLOY_SSH_KEY` | Secret | Закрытый SSH-ключ пользователя развёртывания сайта загрузок |
| `DEPLOY_HOST` / `DEPLOY_USER` | Secret | Адрес и имя пользователя сайта загрузок |
| `UPDATE_BASE_URL` | Variable, необязательно | По умолчанию `https://tifmrcview.com/tifmrcview` |
| `DEPLOY_PATH` | Variable, необязательно | По умолчанию `/var/www/tifmrcview` |

## Структура проекта

| Путь | Содержимое |
| --- | --- |
| `src-tauri/src/formats/` | Декодеры: `tiff.rs`, `mrc.rs`, `raster.rs` (PNG/JPEG/…), `mod.rs` |
| `src-tauri/src/` | `lib.rs` (команды, работа с окнами и файлами), `render.rs`, `reslice.rs` (виды XZ/YZ), `image.rs`, `imod.rs` (модели IMOD), `mem.rs`, `assoc.rs` (регистрация программы по умолчанию), `update.rs` |
| `src-tauri/src/plugins/` | Нативные части плагинов (`recorder.rs`, `mp4.rs`), пакеты плагинов (`package.rs`) и хост WebAssembly для плагинов форматов (`wasm.rs`, `recipe.rs`, `registry.rs`) |
| `src-tauri/examples/probe.rs` | Утилита для проверки декодирования |
| `ui/` | Фронтенд на чистом HTML/JS: `index.html`, `app.js`, `style.css`, `plugin-host.js`; встроенный языковой плагин — `ui/plugins/i18n.js` |
| `plugins/<id>/` | Исходники устанавливаемых плагинов (`recorder` и плагины форматов `zeiss`, `lasx`, `nis`, `fluoview`, `imaris`, `gatan`, `thermo` и `tvips`, по одному на производителя, — крейты Rust, собираемые в WebAssembly) и SDK плагинов (`sdk`) |
| `scripts/` | `pack-plugins.mjs` (собирает zip-файлы плагинов и индекс каталога), `make-release.mjs` |
| `docs/shots/` | Скриншоты для этого README |
| `packaging/linux/` | Файлы упаковки для Linux (MIME-тип для .mrc) |
| `.github/workflows/` | `build.yml` (сборка и релиз), `plugins.yml` (пакеты каталога плагинов) |
